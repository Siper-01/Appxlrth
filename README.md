# Appxlrth

> 免费的逆向分析与应用保护工具箱
> 最新版本：**1.0.4**
> 作者：S.E.Siper（小迁）

Appxlrth 是一款面向 Android 应用开发者与逆向学习者的**一体化工具集**，同时覆盖「逆向分析」与「应用加固保护」两条主线。它既可以帮助你分析、调试、脱壳 APK，也可以帮助你为自己的应用加上多层防护，抵御静态逆向、动态调试乃至当下流行的 AI 一键逆向。

简单理解：**应用破解 + 应用保护，一个工具全包。**

---

## 项目背景

作者在 3 月 22 日发布了 Appxlrth 1.0.1。由于当时是测试版，采用了订阅试用方案（私聊发暗号即可获得使用），或许是因为被检测到需要付费，帖子被删除。此后项目转为**完全免费、公益化运营**，有能力的用户可以赞助支持，助力持续更新。

最近 AI 逆向的能力越来越超前，许多软件即使加固得「五颜六色」，依然能被轻松还原。独立开发者耗费大量时间打磨的项目，成果却被一键扒取，心血付诸东流。为此，Appxlrth 在 1.0.4 中引入了全新的 **Appxlrth V** 加固内核，将多项防护能力统一收纳，并专门针对 AI 逆向场景做了对抗设计。

## 最新版本：1.0.4

### 更新内容

1. **引入 Appxlrth V 工具**，具体包含 Appxlrth 加固、Dex Protect、So Protect、Vmp、防 AI 逆向。将多项防护能力统一收纳到全新内核当中。

3. **新增 Mcp 服务合集**，目前收录 MT（mt mcp）、NexusBridge（r2 mcp / unidbg mcp / logfox mcp），打通工具之间的联动调试链路。
4. **新增 Apk 在线脱壳**，一键 Dump 加密保护的 Dex 文件。某数字加固还不能脱出，仅针对市面主流加固方案生效。

### Appxlrth V —— 一键式保护工具

Appxlrth V 是全新的整合式加固内核，把旧版分散的防护功能合并统一，防护强度全面升级，省去分步配置的繁琐操作，普通开发者也能快速上手。

核心能力：

- **Appxlrth 加固** —— 一键综合加固：Dex 加密加壳 · So 分析防护 · 自动重签名
- **Dex Protect** —— 类名混淆 + 字符串 XOR 加密，隐藏代码结构与敏感字符串
- **So Protect** —— ELF 结构分析、.text 段加密、完整性校验与加固报告
- **Dex2c** —— Dex 转 Native 代码
- **VMP 2.0** —— 抽取 Activity 方法到 Native 虚拟机执行
- **防 AI 逆向** —— 专属代码污染防护，干扰各类 AI 模型解析

> VMP 虚拟化会抽取业务方法至原生层执行，静态分析很难拿到真实逻辑。唯一缺点是抽完之后软件虽然能正常打开，但 UI 也「神游去了」。
>
> 防 AI 逆向仅干扰 AI 自动解析，**无法完全阻挡人工深度逆向**，不要当做绝对安全的屏障。

### Apk 在线脱壳

用于日常快速提取 Dex 做分析调试，不作为商业逆向用途。强防 Dump、做过反调试处理的安装包会直接脱壳失败，属于对抗层面的正常现象。若脱壳失败，可尝试网页版 56.al 备用。某数字加固暂不支持。

## 功能详解

### 1. 分析注入

识别市面已知的所有加固，根据状态对症逆向，原理本质就是通过特征进行识别。

### 2. Appxlrth 弹窗注入

给 Appxlrth 注入弹窗，内容编辑可在 dex 文件中修改。

> **注意**：来源于国外大佬制作。若注入失败，可手动操作：在 MT 管理器中提取 Appxlrth 拆包，找到 `Resources.zip` 放入指定 apk。之后在 `MainActivity` 的 `OnCreate()` 中添加代码：
>
> ```smali
> invoke-static {p0}, Lcom/Appxlrth/custom/dialog/Customdialog;->zenx(Landroid/app/Activity;)V
> ```
>
> MainActivity 可使用 MT 管理器中的 Activity 记录。

### 3. iApp 代码混淆

一键给 iAppv3 代码混淆。目前可选择：

- **基础**（官方混淆）
- **普通**（函数加密、代码 Token 化、控件 Attribute 抽取）
- **v3 代码混淆**：新增代码 Token 化、控件属性抽离、动态加密，更好地保护 v3 代码

### 4. iApp Decrypt

一键解密 iAppv3 项目打包应用，支持：

- **最新**（新增缓存密钥，支持随机动态库）
- **新版过渡期**（新增本地密钥）
- **改版后密钥**（10 位密钥）

### 5. Dex 反编译

一键反编译 APK 中的 Dex 文件为 Smali / Java 源码，支持批量处理、自动修复异常结构、导出可读工程。

### 6. Res 资源混淆

对 APK 资源文件进行缩短重命名，res/drawable/layout 路径混淆、资源 ID 随机化、arsc 压缩优化。

### 7. Xml 转 Java

将 AndroidManifest 及 Layout 的 Xml 配置反向生成为等效 Java 代码，便于二次开发与分析。

### 8. Assets 加密

对 assets 目录下的配置文件、脚本、数据文件进行 AES 加密，运行时动态解密加载。
（由群友 @小猪 投稿，目前测试一切正常。）

### 9. Ai 辅助分析

基于 AI 智能识别代码结构、定位关键逻辑、自动标注敏感 API 调用、生成分析报告。支持 custom API 接入。
（由群友 @飞鸟 投稿。）

> 由于时间有限，且大模型 AI 使用次数增加 Token 费用也随之增高（作者资金有限）。如要使用 Ai 辅助分析功能，可点击「推荐工具」，里面有 MT 论坛大佬分享的 Apk Analyzer 工具。

### 10. Mcp 服务合集

聚合 MT（mt mcp）、NexusBridge（r2 mcp / unidbg mcp / logfox mcp）多款逆向服务，方便把本工具和其他逆向生态串联，满足不同场景下的调试分析工作。

## 已知问题

1. **闪退问题说明**：进入 App 后请等待几秒，待 Initialization 完成后再操作，过快点击可能导致 Crash。
2. 部分功能说明：Appxlrth 加固、DexProtect、SoProtect 在 1.0.3 中仍处于 Test 阶段；1.0.4 已将这些能力迁移至 Appxlrth V 统一迭代。
3. Ai 辅助分析：由于时间有限，且大模型 AI 使用次数增加 Token 费用也随之增高（作者资金有限）。如要使用可点击「推荐工具」，里面有 MT 论坛大佬分享的 Apk Analyzer 工具。
4. 大文件处理：目前整套加固运算全部运行在本地设备，大体积 APK 处理时 CPU 与内存压力非常大，效率并不理想。文件体积越大，内存占用越高，低配置设备更容易出现异常。遇到闪退可以尝试拆分资源、减小原始安装包体积后再次操作。
5. 脱壳失败：强防 Dump、做过反调试处理的安装包会直接脱壳失败，属于对抗层面的正常现象。可尝试网页版 56.al 备用。某数字加固暂不支持。
